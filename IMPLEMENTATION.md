# Implementation ledger

## Acceptance contract

- Real incremental development with at least ten substantive commits.
- Deterministic offline demo and separate real Overture ingestion.
- Belgium boundary filtering, pinned releases, validated publication.
- Transactional change capture, replay, historical dimensions, late corrections.
- Executed Spark workload and tested local SQL models.
- Dashboard, orchestration, CI, runbooks, and honest verification report.
- Cloud provisioning and public publishing require separate authorization.

## Environment discovery

Python 3.14 and uv are installed. Docker CLI is installed but the Docker engine is unavailable. Java is not available on PATH. These constrain PostgreSQL and Spark execution until resolved. No component is considered tested merely because its configuration exists.

## BYOP

The supplied instructions require original public history, accepted licensing, no secrets or personal data, and genuinely planned future work. They do not prescribe a minimum commit count. Acceptance is determined by the organizers.
